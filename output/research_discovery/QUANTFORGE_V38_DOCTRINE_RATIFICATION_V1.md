## 1. RATIFICATION VERDICT

**V38 DOCTRINE RATIFIED.** QuantForge formally adopts the Assembled-Decision / Relational Qualification Doctrine: a conditional/state/event component need not possess positive standalone expectancy to be useful, but it may contribute to economic qualification only by demonstrating **incremental value over a legitimately validated Base**, under one coherent execution and cost model, with the firewalls, depth limits, and prospective-registration rules of Clauses D1–D25. The **BASE REGISTRY IS EMPTY** as of this ratification and remains empty — this ratification creates no Base, no Conditional Component, no relational hypothesis, and no registry. **No research was executed.** G1 V3, the V26 State doctrine, the Relational Framework Governance V1, the System Assembly Candidate Register V1, and all historical candidate records are unmodified.

Decision basis, stated transparently: ratification items resting on the project owner's explicit positions (posture decision, critique of the predecessor proposal, and the architecture-audit mandate) are marked EXPLICIT OWNER POSITION; items the owner did not address individually but which this ratification task was directed to determine (depth defaults, registry option, minimum artifact architecture) are marked RATIFICATION-TASK DETERMINATION, grounded in the owner-endorsed principles (no permutation mining, no retroactive selection, preserve the production qualification bar) and the architecture audit's recommendations. All are recorded below so no authority is implied beyond what exists.

## 2. APPROVED ARCHITECTURE

```text
BASE (registry begins EMPTY; entry only via D2 prospective validation)
  ↓
CONDITIONAL / STATE / EVENT component (admitted for a specific relational purpose)
  ↓
ASSEMBLED DECISION = BASE + predeclared component(s) + ONE execution model + ONE cost model
  ↓
INCREMENTAL ECONOMIC QUALIFICATION (BASE vs BASE+COMPONENT; holistic adjudication)
```

The primary research question made lawful: *Does adding this predeclared conditional component improve this legitimate Base decision?*
The questions kept unlawful: *Is the conditional component profitable by itself?* (never a qualification question), *Can State A rescue State B?* (No-Rescue rule), and *Can artifacts be combined until something becomes profitable?* (permutation prohibition).

## 3. RATIFIED DOCTRINE PROVISIONS (D1–D25)

The full operative text of Clauses D1–D25 of the ratified proposal is adopted verbatim and constitutes the normative doctrine. The ratified provisions in summary:

| Clause | Ratified provision |
|---|---|

| D2 Base validation & viability | Entry only via new prospective Base-validation study (forward-justified scope recorded pre-measurement; outcome-blind; reproducible; realistic costs; measured decision economics); BASE VALIDATED ≠ QUALIFIED ALPHA; qualitative Base viability adjudicated holistically, no numeric cut-off |
| D3 Conditional component | Deterministic, provenance-bearing, G0/MOC-surviving; no positive standalone expectancy required; qualifies only via increment over a ratified Base; "failed standalone → conditional" prohibited as rationale |
| D4 Relational hypothesis | Predeclared: components, relationship, mechanism rationale, expected dependency, expected economic consequence, counterfactual, execution context; no admission on mutual historical interest alone |
| D5 Assembled decision as unit | Assembled Decision = Base + predeclared component(s) + one execution + one cost model = unit of economic qualification; Base opportunity set preserved |
| D6 Incremental qualification | BASE vs BASE+COMPONENT on Base's population/outcome/cost schedule; metrics predeclared; default primary = Base's own economic outcome; holistic; no universal thresholds |
| D7 Single cost/execution | One end-to-end execution, one cost treatment; no independent component charging; no free filters; no component-P&L summation; no double counting; no hypothetical fills |
| D8 No-rescue rule | Rescue framing invalid (SEED-002 = cited counterexample); only increment-over-viable-Base questions admitted |
| D9 Base-registry firewall | Registry EMPTY; no automatic promotion of any historical artifact (CAND-077/081/083/099, H01 incl. contemporary cell, ORD, closed lines) |
| D10 Component admission path | Option C: separate research-stage admission path; System Assembly Candidate Register unchanged, its independent-qualification bar preserved |
| D11 Relational depth | Level 1 default qualification unit; Level 2 requires established Level-1 increments + interaction mechanism rationale + separate registration; Level 3+ prohibited absent separate governance |
| D12 Permutation control | Mechanism-driven predeclared pairings; controlled predeclared batches; no exhaustive search, post-hoc selection/ranking, threshold search, retries |
| D13 Closed-line firewall | Existing rules verbatim; closed candidates = negative knowledge only; new hypotheses require independent justification |
| D14 Protected-forward firewall | CAND-015/024/035 fully excluded; no inspection, relational use, or indirect leakage |
| D15 Temporal/HTF→LTF | Stacks require deterministic definitions, timestamp ordering, no look-ahead, synchronization, max temporal distance, event dependency, counterfactual, one decision, one outcome; practitioner terminology operationalized before admission |
| D16 Liquidity compatibility | Future liquidity hypotheses hostable as Level-1/2 over a ratified Base via full admission; remain FUTURE UNVALIDATED HYPOTHESIS; no thresholds/definitions created |
| D17 Lifecycle | Characterization ≠ admission ≠ qualification ≠ production readiness; Base validation a parallel path |
| D18 H01 | H01 remains CLOSED under its original adjudication; contemporary cell = preserved evidence / candidate-Base hypothesis only; any future modern-era study newly registered, forward-justified, outcome-blind, not a reopening |

| D22 Anti-p-hacking | Full firewall compilation adopted (prospective registration; no post-hoc Base; no subset promotion; no exhaustive combinations; predeclared pairings; mechanism; depth; no tuning/metric-shopping/period-selection/retries; firewalls; one cost model; counterfactual; no result-informed redesign) |
| D23 Governance ownership | Approvals per Section 19 table of the proposal (owner + existing adjudication conventions); no self-authorization |
| D24 Registry architecture | Minimum: Base Registry (empty); Conditional-Component Admission Ledger (research stage); relational hypothesis registrations (existing framework); increment evidence records (evidence ledger). No fifth registry. Assembly Register untouched |
| D25 Stop rules | Qualitative stops adopted (no Base → no assembled test; no counterfactual → no experiment; permutation-driven → stop; post-hoc admission → reject; repeated negative increments → pause/close family; cost incoherence → stop); no bps gates |
